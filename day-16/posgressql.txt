5  Cascade Delete — Trace and Verify    —  Challenge
Read each scenario and write the expected outcome WITHOUT running the code first. Then verify by running it.

Setup — Run this SQL to create and fill 3 connected tables:

CREATE TABLE authors (
    id   INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);

CREATE TABLE books (
    id        INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    title     VARCHAR(200) NOT NULL,
    author_id INTEGER NOT NULL,
    CONSTRAINT fk_books_author
        FOREIGN KEY (author_id)
        REFERENCES authors(id)
        ON DELETE CASCADE
);

CREATE TABLE reviews (
    id      INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    content TEXT NOT NULL,
    book_id INTEGER NOT NULL,
    CONSTRAINT fk_reviews_book
        FOREIGN KEY (book_id)
        REFERENCES books(id)
        ON DELETE SET NULL   -- different from CASCADE!
);

-- Insert data
INSERT INTO authors (name) VALUES ('Author One'), ('Author Two');
INSERT INTO books (title, author_id) VALUES ('Book A', 1), ('Book B', 1), ('Book C', 2);
INSERT INTO reviews (content, book_id) VALUES ('Great!', 1), ('Okay', 2);

💡 Hint: CASCADE: delete parent → all children delete too. SET NULL: delete parent → child's FK column becomes NULL (child row still exists). PROTECT: you CANNOT delete parent while children exist. ON DELETE CASCADE in books means delete Author 1 → Book A, B vanish. SET NULL on reviews means reviews survive but book_id becomes NULL.
